Только если в промпте твоей задачи есть строка `[flow-handoff] slug=<child> parent=<p> step=<S>`: веди {FLOW_DIR}/<child>.md как тихое зеркало статуса своей работы. Твоя задача и инструкции важнее; файл не должен менять то, как ты работаешь.
---
title: <короткий заголовок, без #>
status: active | blocked | done
parent: <p>
parent_step: <S>
---
## Steps
- [ ] S1 <текст>
## Journal
- plan #plan — <N шагов>
Плоский список шагов сразу под ## Steps; маркеры [ ] не сделан, [x] сделан, [-] пропущен (почему), [!] блокер (почему); маркера «в работе» нет. Журнал только дописывать: `- <type> [S<n>] — <текст>`, типы plan, step, deviation, decision, blocked, info. На законченный шаг: [x] + строка step одним сообщением, параллельно со следующим рабочим вызовом (никогда не отдельным ходом); `status: done` вместе с последним шагом. Правь только через Write/Edit, никогда через Bash.
Без этой строки в промпте: никогда не создавай и не правь файлы в .flow/.
